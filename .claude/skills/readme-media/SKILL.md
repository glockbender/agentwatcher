# Ролики и картинки README

В README два вида иллюстраций:

- **Картинки** (`docs/images/*.png`, `lamps.gif`) рисуются из кода: `task readme-images` и
  `task readme-menu`. Этот скилл их не касается.
- **Ролики** (`docs/images/clip-*.avif`) снимаются с экрана: демо-копия приложения, три сессии
  Claude Code в Ghostty, сценарий кликает и печатает сам. Об этом скилл.

Какой ролик что показывает и где стоит — `scripts/clips.txt` и строки `<img src="docs/images/clip-…">`
в README. Переснимать стоит те, чей сюжет изменился: подпись, раскладка окна, новый шаг.

Снимают в чистой macOS внутри виртуальной машины Tart: как собран стенд, что владелец делает
руками один раз и почему — в [vm.md](vm.md). Монтаж (`cut.py`) идёт на Mac, как и раньше.

## Шаги

```sh
S=.claude/skills/readme-media/scripts
$S/vm.sh up bare                 # копия стенда и сборка, ничего не открыто
$S/vm.sh shoot                   # все дубли по порядку; упал — vm.sh shoot <шаг> идёт с него
$S/vm.sh fetch                   # записи и отметки — в кэш на Mac
$S/cut.py --sheet --publish      # ролики, раскладки кадров, копии в docs/images
$S/vm.sh down                    # копия удаляется
```

`vm.sh shoot` снимает по шагам, и каждый шаг ждёт то, что оставил предыдущий:

| Шаг | Что снимает |
| --- | --- |
| `setup` | первый запуск: гид ставит хуки, новая сессия доходит до виджета |
| `stage` | не дубль: три сессии, «Check the task list» ждёт ответа |
| `start` | открывающий ролик: карточка ждущей строки, клик → вкладка с вопросом |
| `menu` | то же через меню |
| `settings` | порядок, тема, части строки; до и после — настройки по умолчанию |
| `fullscreen` | терминал на весь экран и точка в углу; завершает остальные сессии |
| `icon` | значок и одна сессия в маленьком терминале под ним |
| `counts` | то же в виде Counts; последним — оставляет значок в этом виде |

Дубль установки — первым, только в машине и только на новой копии: он ставит хуки, которых там
ещё нет, а в конце завершает все `claude` и закрывает Ghostty. Вне машины он отказывается
работать.

Перезапущенная копия (`reset-settings`) показывает сессию, от которой ещё не было события, как
«no signal» — серым кольцом, которым README обозначает потерянную сессию. Поэтому `reset-settings`
даёт каждой сессии сцены короткий ход. Событие, пришедшее, пока копия перезапускается, теряется:
конец хода, отвеченного перед самым перезапуском, пропал, и сессия выглядела ждущей. Поэтому
`reset-settings` сначала ждёт, пока все сессии закончат ход.

Каждый дубль пишет `<дубль>.mov` и `<дубль>.marks` в `~/Library/Caches/agent-watch-media`
машины, `fetch` переносит их в тот же каталог на Mac; там же кадры, ролики и раскладки. Дубль
можно повторить отдельно: `vm.sh run takes/<дубль>.sh`; перед повторным дублем настроек —
`vm.sh run stage.sh reset-settings`. Ролики режутся и по одному: `cut.py --sheet clip-menu`.
Если сцена встала на полпути, `vm.sh shoot stage` поднимает её заново и снимает всё, что после.

### Долгие шаги

| Шаг | Сколько идёт |
| --- | --- |
| `vm.sh stand` | около 6 минут |
| `vm.sh up`, `vm.sh up bare` | 1–3 минуты, смотря сколько собирать |
| `vm.sh shoot` | около 5 минут, дубль — 10–40 секунд |
| `vm.sh fetch` | переносит только новые дубли, от 0,05 до 0,6 ГБ каждый |
| `cut.py --sheet` | около 12 минут на девять роликов, по четыре сразу |

Шаг дольше пары минут запускается в фоне, и его конец ждут по уведомлению, а не циклом с
`sleep`. Пока команда в переднем плане идёт, сообщения владельца до Claude не доходят, и
молчание выглядит как зависание. Перед долгим шагом — одна строка владельцу: что запущено и
сколько примерно идёт. В фон команду отправляет сам инструмент (`run_in_background`): с `&!`
внутри команда кончается сразу, и уведомления о конце шага нет.

### Без машины

Те же сценарии, кроме `takes/setup.sh`, работают и на своём экране: `stage.sh up`, `takes/*.sh`,
`stage.sh down` вместо `vm.sh`. Тогда дубль двигает мышь владельца и печатает в окна на его экране — на это нужно
согласие, и пока идут дубли (около 5 минут), владелец не трогает мышь и не переключает рабочие
столы: запись снимает активный стол. Ещё нужно от владельца:

1. **Пустой рабочий стол** справа от текущего: `aw-media space right` переходит на него,
   `aw-media onscreen` там ничего не выводит.
2. **Своя копия Agent Watch выключена**, иначе в строке меню два значка. `stage.sh up` откажется
   стартовать, пока она работает.
3. **Место в строке меню.** Примерно через 11 секунд записи macOS ставит у левого края значков
   индикатор записи, и на экране с вырезом крайний левый значок — часто наш — уходит за вырез
   (замер: macOS 15.3). Нужен запас шириной в один значок; дубль со строкой меню в кадре
   проверяет это сам и останавливается с подсказкой.
4. **«Не беспокоить».** Уведомления других приложений попадут в кадр. Перед каждым дублем
   `aw-media clear-notifications` закрывает уже показанные, новые он не остановит.
5. **Разрешения.** `aw-media check` — Accessibility, запись экрана, синтетические события. macOS
   спрашивает их не у Claude.app, а у внутреннего `claude.app` из
   `~/Library/Application Support/Claude/claude-code/<версия>/…/claude.app`, через который
   запущены команды (замер: macOS 15.3, Claude Code 2.1.289). Выдаёт владелец.
6. **Хуки Claude установлены** из приложения (Tooling): `stage.sh up` берёт их из плагина
   `~/.claude/skills/agent-watch/hooks/hooks.json` и направляет в демо-копию.

Расшифровки демо-сессий тогда ложатся в историю владельца
(`~/.claude/projects/-Users-…-CommonProjects-agent-watch/`): удалять их или нет, решает он.

## Как вести съёмку

- **Новый вид или раскладка — сначала один ролик владельцу**, потом остальные: дубль
  (`vm.sh run takes/<дубль>.sh`), `fetch`, `cut.py --sheet <ролик>`. Замечание к одному ролику
  обычно касается всех.
- **Место окна, которое ставит не сценарий, мерить в машине до дубля.** Окно настроек ставит
  macOS, новый терминал — конфиг Ghostty; рамку печатает `aw-media ax windows <pid>`. Посчитанное
  место ошибалось трижды: меню вне сцены, окно, урезанное краем экрана, терминал на 65 точек ниже
  окна настроек.
- **Раскладку дубля видно по его последнему кадру** — сразу после `fetch`, до монтажа на 12
  минут: `ffmpeg -sseof -1 -i ~/Library/Caches/agent-watch-media/<дубль>.mov -frames:v 1 last.png`.

## Проверить до коммита

- **Раскладка каждого ролика** (`<ролик>-sheet.png`, кадр каждые полсекунды): вся сцена в кадре,
  без пустых полос по краям и без строк, обрезанных краем кадра; начало и конец не обрезают
  действие. Полноэкранный терминал пишет от левого края экрана, поэтому его ролик — весь экран.
- **Изменение, ради которого снят ролик, видно.** Клик дошёл — ещё не значит, что что-то
  сдвинулось: в ролике порядка ждущая строка и так стояла первой, и «By state» ничего не менял.
  Теперь разрешения просит нижняя строка виджета; дубль находит её сам, потому что строки встают
  в порядке первых событий сессий, и он меняется от сцены к сцене.
- **Строка меню:** в машине она резкая — там нет ничего личного. Дубль на своём экране размывает
  всё, кроме значка; вокруг смены ширины значка (Sphere → Counts) кадр раскладки может
  проскочить: смотреть все кадры этого места (`ffmpeg … -vf "crop=…,tile=1x14"` по
  `frames/<ролик>/f*.png`).
- **Чужого в кадре нет:** уведомлений, файлов рабочего стола (они видны на любом столе — сцену
  целиком закрывают окна), почты и названия организации (их прячет `IS_DEMO=1`), путей, кроме
  `~/CommonProjects/agent-watch`, строк чужих сессий (виджет и сводка меню).
- **Размер и лишние файлы.** `cut.py --publish` печатает размер всех роликов — сейчас около
  1,8 МБ на девять — и называет ролик, который есть в `docs/images`, но не в `clips.txt` или
  README: переименованный ролик оставлял там старый файл. Вырос ролик — проверить, не стоит ли в
  кадре что-то мигающее, или поднять `CRF`.
- **После пуша ветки** открыть README на её странице на GitHub и только потом переносить в main:
  показ AVIF на GitHub проверяется только так.

Чего не проверять: **текст в терминале — фон.** Ролик смотрят ради виджета, меню и значка, и что
ответил Claude, не важно: ответ, споривший с ответом из соседнего ролика, и предупреждение о
лимите аккаунта переснимать не стоит (решения владельца, 2026-10-09 и 2026-10-10). Переснимают,
когда ломается то, что ролик показывает. Сверка отметок с кадром (`activity.py <дубль> <с> <по>`
печатает, когда и где менялся кадр) нужна только дублю на своём экране: там по отметкам идёт
размытие строки меню.

## Когда изменился интерфейс

- **Подписи.** Сценарий находит элемент по тексту Accessibility: `click find <конец текста>` или
  `click findc <часть текста>`. Дерево Accessibility держит пункты меню и закрытым, и поиск по
  концу текста берёт первое совпадение — «Hide Widget» тоже кончается на «Widget».
- **Раскладка окон.** Координаты окон в `takes/*.sh` — точки экрана; сцена дубля (`STAGE`) — его
  кадр. Рамки камеры в `clips/*.keys` — пиксели сцены: `(точка − начало сцены) × 2`. Строка
  `.keys`: момент (`@отметка±секунды`), x, y, ширина рамки; высота следует из размера ролика.
  Одна строка — камера стоит; между двумя разными строками она плавно едет.
- **Новый ролик:** строка в `clips.txt` (имя, дубль, начало, конец, размер, файл рамок), рамки в
  `clips/`, при нужде новая отметка в дубле (`mark <имя>` или `click … <имя>`).

## Решения

- **AVIF, а не видео.** GitHub вырезает `<video>` со ссылкой на файл репозитория; MP4 играет только
  загруженный в комментарий (`user-attachments`) — вне репозитория и по кнопке Play. Анимированный
  AVIF — картинка: играет сам, по кругу, лежит в git. На одном 5-секундном ролике: AVIF 160 КБ,
  WebP 580–790 КБ, MP4 295 КБ. Показывают Chrome, Firefox 113+, Safari 16+ (macOS 13+).
- **Без LFS.** Все ролики вместе около 1,8 МБ, примерно как остальные картинки README. LFS
  потребовал бы `git-lfs` у каждого, кто клонирует, настройки CI и тратил бы квоту. Каждая
  закоммиченная версия остаётся в истории навсегда, поэтому ролики коммитят один раз, после
  одобрения.
- **Камера стоит, кадр — вся сцена и ничего вокруг.** Наезды прятали детали и сами изменения,
  ради которых снят ролик (решение владельца, 2026-10-09). Пустой стол по краям кадр отрезает, а
  окна стоят вплотную друг к другу (решение владельца, 2026-10-10): в ролике установки терминал
  кончается вровень с окном настроек, и кадр — от окна настроек до виджета. Экран машины —
  1152×720 точек: весь экран при показе шириной 800 даёт интерфейс примерно в 70 % натуральной
  величины, кадр поменьше — крупнее. Окна, которые macOS ставит сама, — окно настроек по центру,
  новый терминал, — встают здесь рядом с виджетом. Масштаб интерфейса в macOS и есть число точек
  экрана, а настройка размера виджета показала бы не то, что получает человек по умолчанию.
- **Размер вдвое больше показа** (1600 для `width="800"`): на Retina чётко. Источник уже 2×, так
  что весь экран (2304 пикселя) — уменьшение.
- **25 кадров/с; CRF 46** (`libsvtav1`, SVT-AV1 4.1, `scm=1` — режим для экранного содержимого).
  На CRF 46 мелкий текст терминала и цифры виджета не отличались от исходника на глаз.
- **Промежуточные кадры — PNG.** Промежуточный ProRes сжимает с потерями, неподвижные места
  меняются от кадра к кадру, и кодировщик пересжимает их каждый раз.
- **Рамку режет Core Image (`aw-media zoom`), не `zoompan`.** Он же делает наезд, если сюжету он
  понадобится: `zoompan` округляет рамку до целых пикселей, и медленный наезд дрожит.
- **Запись — ScreenCaptureKit и ProRes** (`aw-media record`), а не `ffmpeg`: в машине его захват
  не набирал и 25 кадров в секунду. Замеры — в [vm.md](vm.md).
- **Отметки во времени записи.** Запись сама пишет время своего первого кадра (`<дубль>.t0`), и
  отметки дубля отсчитываются от него. Раньше отметки расходились с записью на 0,4–3 с, их
  подгоняли вручную, и размытие однажды встало на 1,4 с раньше смены значка.
- **Рамки — из дубля.** Сценарий пишет рамку всего, по чему кликает, а сэмплер — рамку значка
  каждые 0,1 с. Размытие строки меню и его «окно» вокруг значка строятся из них; вокруг смены
  ширины резким остаётся только общее для обеих рамок.

## Ловушки

- **Claude Code в демо-сессиях** (замер: Claude Code 2.1.293):
  - `IS_DEMO=1` прячет почту и организацию, но пропускает вопрос о доверии к папке, не сохраняя
    ответ, а хуки работают только в доверенной папке. Поэтому сессии запускаются в основной
    папке репозитория.
  - `--setting-sources project,local` отключает настройки пользователя вместе с плагинами, и
    хуки приходят через `--settings`.
  - Массивы настроек складываются из всех источников, поэтому слова спиннера заменяются только
    так.
  - Ещё флаги: `--strict-mcp-config` убирает предупреждение MCP, `--permission-mode default` —
    если у владельца по умолчанию auto. Настройка
    `"preferredNotifChannel": "notifications_disabled"` гасит уведомление «Claude needs your
    permission».
  - Через несколько ходов сессия спрашивает «How is Claude doing this session?» прямо в
    терминале; `CLAUDE_CODE_DISABLE_FEEDBACK_SURVEY=1` в `env` настроек демо-сессий это
    выключает (замер: Claude Code 2.1.294).
  - Имя сессии появляется в виджете после первого вопроса.
- **Демо-копия** показывает все процессы Claude и Codex на машине. `aw-media ax dismiss <pid>
  <имена>` закрывает чужие строки и оставляет демо-сессии; дубль делает это перед записью.
  Закрытая строка живёт только в памяти и возвращается со следующим событием своей сессии.
  Настройки копии лежат в её папке (`settings.json`): настройки владельца она не трогает.
- **Ghostty** (замер: Ghostty 1.3.1): окно закрывает `close window`, не `close`. Сессия
  запускается через `exec claude`, так что с концом сессии закрывается вкладка, а с последней — окно.
- **Уведомления.** Баннер закрывает действие Accessibility «Close» — то же, что его ×. «Press»
  открыл бы приложение (замер: macOS 15.3).
- **Клик — с плавным подводом мыши** (`aw-media glide … click`): мгновенный перенос пропускает
  наведение, от которого зависит клик.
- **Строка сессии есть и в виджете, и в меню**, и поиск по тексту находит сначала виджет. Пункт
  открытого меню ищет `click findm`: только среди элементов внутри меню.
- **Первое меню копии может не открыться.** Клик по значку начал меню — окно терминала стало
  неактивным, — а меню так и не появилось; следующий клик открыл его как обычно (замер: macOS
  15.7.7 в машине, один раз из нескольких прогонов). Поэтому дубль, который открывает меню,
  сначала открывает и закрывает его вне записи: `warm_menu`.
- **Запись не должна пережить сценарий.** Без SIGINT она не дописывает индекс, и файл не
  читается, а оставленная работать растёт до 27 МБ в секунду и держит `tart exec`. `lib.sh` ставит
  `trap at_exit EXIT`: при любом выходе запись останавливается, а в отметки дописывается
  `failed`. Своё прибирание дубль добавляет в `AT_EXIT`; свой `trap … EXIT` заменил бы общий. В
  `zsh` `trap … EXIT` внутри функции срабатывает при выходе из функции, а не из сценария.
- **В полноэкранном ролике две точки в углу**: точка приложения и фиолетовая точка записи экрана,
  которую macOS ставит туда, пока строка меню спрятана (замер: macOS 15.7.7 в машине). Вторую
  рисует система, пока идёт запись; убрать её нечем.
- **Клик иногда теряется** без видимой причины: по строке виджета на только что запущенной
  копии, по «Order» в настройках; однажды карточка строки показалась при спрятанном виджете.
  Причина не найдена ([docs/implementation-plan.md](../../../docs/implementation-plan.md),
  «Сбои, которые не повторились»); такой дубль переснимают.
- **Скриптовые мелочи:**
  - `pgrep -f <путь>` находит и оболочку, в чьей команде этот путь.
  - SVT-AV1 печатает свои настройки при любом уровне логов `ffmpeg`.
  - В AVIF два потока, картинка и анимация: кадры читаются с `-map 0:1`.

## Что можно улучшить

- Режим демо в самом приложении: не подхватывать процессы, запущенные до него, вместо закрытия
  чужих строк.
- Начинать запись до расстановки окон: 11 секунд ожидания индикатора уйдут в подготовку.
- Строить рамки камеры по рамкам из отметок, а не писать их числами.
- Убрать чёрное окно Ghostty, которое мелькает на 1–2 кадра при открытии терминала
  ([vm.md](vm.md)).
