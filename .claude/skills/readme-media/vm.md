# Стенд в виртуальной машине

Как ролики README снимаются в чистой macOS внутри виртуальной машины Tart: из чего собран стенд,
что делает владелец своими руками и почему так. Сценарии дублей, монтаж и проверки роликов — в
[SKILL.md](SKILL.md).

## Зачем машина

- **В кадр не попадает рабочий стол владельца**: значки строки меню, вырез экрана, уведомления,
  файлы, строки чужих сессий.
- **Синтетический ввод остаётся внутри машины.** Дубль двигает мышь и печатает, а владелец в это
  время работает: окно машины на его экране не открывается.
- **Первый запуск снимается на чистой системе**: без хуков, без настроек, без следов прошлых проб.

## Три машины

| Машина | Что в ней | Сколько живёт |
| --- | --- | --- |
| `aw-golden` | образ `ghcr.io/cirruslabs/macos-sequoia-base` без изменений: macOS 15.7.7, Homebrew, Command Line Tools, `tart-guest-agent` | всегда; только клонируется |
| `aw-stand` | golden и всё для съёмки: размер экрана, `ffmpeg`, Ghostty, Claude Code, Claude.app ради значка, `task`, два разрешения, одобренные настройки организации. Аккаунта нет | собирается один раз |
| `aw-take` | копия стенда на одну съёмку, с токеном | до `vm.sh down`: копия удаляется вместе с токеном, мимо корзины |

Tart 2.40.1 стоит из релиза на GitHub (формула в их Homebrew-репозитории сломана): программа в
`~/Applications/tart.app`, ссылка `~/.local/bin/tart`. Golden получен командой
`tart clone ghcr.io/cirruslabs/macos-sequoia-base:latest aw-golden`, это около 25 ГБ загрузки.
Клоны делят блоки диска с исходником (APFS), поэтому `du` показывает у каждой по 30 ГБ, а
занимают они меньше.

## Один раз — владелец

1. **Токен Claude Code в связку ключей Mac.** Скрипты берут его оттуда и не видят его значения:

   ```sh
   claude setup-token
   ```

   ```sh
    security add-generic-password -a "$USER" -s agent-watch-vm-claude-token -w
   ```

   Пробел в начале не пускает вторую команду в историю `zsh`; `-w` без значения заставляет
   `security` спросить токен, а не взять его из командной строки.
2. **`vm.sh stand`** собирает стенд сам, около шести минут, окна не открывает. Если организация
   управляет настройками Claude Code, нужна `AW_APPROVE_MANAGED_SETTINGS=1` (ниже).
3. **`vm.sh grant`** открывает стенд в окне на экране владельца. Владелец дважды нажимает `Allow`:
   `tart-guest-agent` управляет Ghostty, затем AgentWatch управляет Ghostty. Окно закрывается само.

Почему разрешения руками: это вопрос защиты macOS (TCC), и его смысл в том, что согласие даёт
человек. Запись в базу согласий напрямую автоматическая проверка безопасности Claude Code
отклонила как ослабление защиты, а клик по вопросу синтетическим событием — то же самое другим
путём. Оба разрешения остаются в стенде, и каждая копия получает их готовыми.

**Настройки организации.** При первом старте Claude Code с токеном владельца показывает «Managed
settings require approval»: организация владельца отправляет телеметрию на свой коллектор (замер:
Claude Code 2.1.294). Без одобрения Claude не стартует. Владелец разрешил нажимать его скрипту
(2026-10-09) для своего аккаунта и своей организации. Скрипт нажимает только с
`AW_APPROVE_MANAGED_SETTINGS=1 vm.sh stand`; без переменной стенд останавливается и печатает экран
Claude. Для другого аккаунта или другой организации спросить заново.

## Съёмка

Шаги — в [SKILL.md](SKILL.md): `vm.sh up bare`, `vm.sh shoot`, `vm.sh fetch`, `cut.py`,
`vm.sh down`.

Дубль установки снимается первым: он требует машину, где хуки ещё не стояли и ничего не открыто.
Повторить его можно только на новой копии (`vm.sh down`, `vm.sh up bare`). Остальным дублям
установленный плагин не мешает: сессии сцены запускаются без настроек пользователя.

`vm.sh sh <команда>` выполняет команду в копии — посмотреть на экран:
`vm.sh sh "screencapture -x '/Volumes/My Shared Files/aw/screen.png'"`. Каждый `zsh` в копии
читает токен в окружение (`~/.zshenv`), поэтому `vm.sh sh env` и `vm.sh sh set` печатают токен.

Неудачный дубль пишет в свои отметки строку `failed`, и `vm.sh fetch` его не забирает: на Mac
остаётся прежняя удачная запись. Забрать его всё равно — `vm.sh fetch <дубль>`.

## Как устроено

- **Экран — 1152×720 точек при плотности 2x**: ролик показывает его целиком или ту его часть, где
  идёт действие (почему — в SKILL.md, «Решения»). `tart set --display` задаёт виртуальный экран,
  но macOS в машине остаётся при своём режиме 1024×768 (замер: macOS 15.7.7). Режим переключает
  `aw-media display`, и `vm.sh` проверяет размер при каждом старте.
- **Строка меню — 25 точек** по `aw-media screen`: выреза нет. Сценарии берут высоту из `$BAR`,
  а не числом.
- **Индикатора записи нет.** На Mac через 11 секунд записи macOS ставит индикатор и сдвигает
  значки; в машине значок не сдвинулся за весь 75-секундный дубль (замер: macOS 15.7.7). Поэтому
  на экране без выреза дубль индикатор не ждёт.
- **Запись — ScreenCaptureKit и ProRes 422** (`aw-media record`). Захват `ffmpeg` (`avfoundation`)
  давал в машине около 22 кадров в секунду при любом размере экрана, ScreenCaptureKit — 57.
  Аппаратного кодировщика в машине нет. Из программных за 30 кадрами в секунду при 3456×2234
  успел только ProRes, не теряя кадров; H.264 терял кадры, HEVC — половину (замер: macOS 15.7.7).
  ProRes — от 7 до 27 МБ в секунду, смотря сколько на экране меняется: дубль весит от 0,17 до
  1 ГБ (замер: macOS 15.7.7). На одной и той же сцене ролик из такой записи весил столько же, сколько
  из прежней H.264: 462 КБ против 466 КБ. Кадр приходит, только когда экран меняется: запись,
  кончавшаяся на неподвижном экране, обрывалась на последнем изменении, и ролик установки потерял
  три секунды с «✓». При остановке `aw-media record` дописывает последний кадр ещё раз, с моментом
  остановки.
- **Разрешения образа.** В образе выключена защита SIP, а `tart-guest-agent` уже имеет
  Accessibility, запись экрана и синтетические события; всё, что запущено через `tart exec`,
  пользуется ими. Управления Ghostty (Apple events) у него нет: `osascript` к Ghostty без
  разрешения не падает, а ждёт ответа на вопрос две минуты и выходит с ошибкой -1712.
- **Приложение собирается на Mac**, подписанное сертификатом `Agent Watch Developer`, и
  копируется в машину (`AW_PREBUILT=1`). Разрешение «AgentWatch управляет Ghostty» привязано к
  подписи: сборка внутри машины подписалась бы заново, и разрешение пропало бы.
- **Токен.** С Mac он идёт трубой в `security -i` машины, поэтому не появляется в аргументах ни
  одной программы. `~/.zshenv` машины хранит команду, которая читает токен из связки ключей, а не
  сам токен. Стенд токен не хранит: после каждого входа с ним `vm.sh` удаляет его и записи
  аккаунта из `~/.claude.json`, в том числе когда первый старт прерван. Копию с токеном
  `vm.sh down` удаляет целиком (`tart delete`), мимо корзины: копии по 30 ГБ копились там и
  хранили токен до очистки (решение владельца, 2026-10-10). Сессии сцены тратят лимит этого
  аккаунта: серия пересъёмок однажды упёрлась в него, и работа встала на 14 минут.
- **Claude Code** — копия программы с Mac, ничего не скачивается изнутри. `~/.claude.json`
  заранее говорит, что знакомство пройдено и папке репозитория можно доверять: хуки работают
  только в доверенной папке, а `IS_DEMO=1` пропускает этот вопрос, не сохраняя ответа. Обновления
  выключены.
- **Ghostty** — копия с Mac, его конфиг и `auto-update = off`: иначе новая копия спрашивает про
  обновления кнопкой в заголовке, и кнопка висит в каждом дубле (замер: Ghostty 1.3.1). Первый
  запуск со своим баннером проходит в стенде.
- **Терминал дубля установки открывается на своём месте:** `takes/setup.sh` дописывает в конфиг
  Ghostty `window-position-x/y` (точки от низа строки меню) и `window-width/height` (ячейки). Окно
  в N строк шрифтом 14 — 36 + 18,5 × N точек высотой (замер: Ghostty 1.3.1). Задать место одному
  окну скриптом Ghostty не даёт — только всем через конфиг. Перед этим на 1–2 кадра мелькает чёрное окно
  поменьше внизу слева (замер: Ghostty 1.3.1); как его убрать, не выяснено.
- **Claude.app — только ради значка**, не запускается. Строка виджета и меню рисует значок
  приложения, а без него — оранжевый круг, похожий на вторую лампу. `vm.sh stand` копирует
  приложение с Mac и регистрирует его в LaunchServices (`lsregister -f`): иначе система нашла бы
  его не сразу.
- **Оболочка для кадра:** `~/.hushlogin` убирает строку «Last login», приглашение — `%~ %#`.
  Набранный `claude` запускается как сессии сцены, если окно открыто с `AW_DEMO_SETTINGS`
  (`open_terminal <имя>`), и как обычный `claude` с настройками пользователя — без неё (дубль
  установки).
- **Обычный `claude`** читает из настроек пользователя слова спиннера сцены и
  `permissions.defaultMode: "default"`: в подвале тогда «manual mode on», как у сессий сцены, а не
  «auto mode on» (замер: Claude Code 2.1.294).
- **Фон рабочего стола — однотонный тёмно-серый** (`Stone.png`, `aw-media wallpaper`). Лес образа
  стоял за каждым дублем и съедал бо́льшую часть размера ролика: черновой ролик установки с ним
  весил 1,57 МБ.
- **Оформление системы — тёмное** (`AppleInterfaceStyle Dark`), как на Mac владельца, где
  размечены дубли. В светлой системе режим виджета «Auto» уже светлый, и выбор «Light» в дубле
  настроек ничего не менял на экране. Настройка вступает в силу при входе, а каждая копия
  стартует со входа.
- **Репозиторий.** В машину уходит текущая ветка и всё незакоммиченное, так что дубль можно
  проверить до коммита. В машине ветка называется `main`: её видно в строках виджета.
- **Хуки.** `stage.sh` берёт список событий из плагина на Mac (`AW_CLAUDE_HOOKS`), в стенде
  плагин не ставится: его ставит гид в дубле установки. Отправитель отладочной копии находит
  приложение только через `AGENT_WATCH_SUPPORT_DIR`: без этой переменной в окружении `claude` хук
  отрабатывает, но событие никуда не доходит. `open_terminal` её передаёт.
- **Файлы** ходят через общую папку: `~/Library/Caches/agent-watch-media/vm-share` на Mac —
  `/Volumes/My Shared Files/aw` в машине.

## Ловушки

- **`tart exec` без `zsh -lc`** не видит Homebrew и `~/.local/bin`.
- **`tart run` должен пережить скрипт**: он запускается как `nohup … &!`, иначе машина
  останавливается вместе с `vm.sh`.
- **macOS открывает при старте то, что работало при остановке.** Ghostty, оставшийся в стенде,
  открылся в копии, и `stage.sh up` отказался работать на непустом столе. `vm.sh` закрывает его
  перед сценой и перед остановкой стенда.
- **Часы машины идут по UTC.** В строке меню время на три часа меньше, чем у владельца.
- **Копия файла только для чтения** (`task` из Homebrew) не перезаписывается обычным `cp`:
  нужен `cp -f`.
- **Claude, убитый `SIGKILL`, засчитывается как сбой полноэкранного режима отрисовки.**
  Запущенный Claude держит в `~/.claude.json` запись о старте (`fullscreenBootPending`) и стирает
  её при обычном выходе. Оставшаяся запись при следующем старте становится «сбоем»
  (`fullscreenBootStrikes`), и после нескольких Claude рисует упрощённо и пишет об этом в каждом
  окне (замер: Claude Code 2.1.294). `claude-first-start.py` завершает Claude через `SIGTERM`, а
  стенд стирает обе записи.
- **`${name:+--name "$name"}` в `zsh` — одно слово:** Claude получил аргумент
  «--name Count the tasks» целиком и отказался стартовать. Функция `claude` в `~/.zshrc` стенда
  собирает аргументы в массив.
- **Файл, перезаписанный на месте в общей папке,** работающая машина читает старым: архив без
  нового сценария, скрипт с нулевыми байтами в конце (Tart 2.40.1). `vm.sh sync` каждый раз
  пишет архив под новым именем.
- **Любая пауза в машине длится не меньше ~50 мс:** `usleep` на 14 мс занимал 49–57 мс,
  `nanosleep` и `Thread.sleep` — так же, с объявленной срочной активностью
  (`ProcessInfo.beginActivity`) и без неё (замер: macOS 15.7.7, Tart 2.40.1). Подвод мыши из 45
  шагов шёл 2,8 с вместо 0,63, набор текста — вдвое дольше. `aw-media` поэтому считает время от
  часов: положение мыши — по прошедшему времени, символы — по расписанию.
- **AppleScript к System Events** в машине ждёт согласия человека, и окно согласия остаётся на
  экране и попадает в кадр. Фон ставит `NSWorkspace` (`aw-media wallpaper`), согласия ему не
  нужно.
- **Поиск кнопки в дереве Accessibility** копии занимает в машине около 1,5 секунды, и экран в
  это время стоит. Паузы перед кликами в дубле установки поэтому короткие.
- **«Connect Agent →» не находится поиском по концу текста** (`click find`), а по части текста
  находится. Почему, не выяснено; кнопки гида дубль ищет по части текста (`click findc`).
