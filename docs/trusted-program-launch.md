# Проверка запуска доверенной программы

Здесь описан изолированный эксперимент с идентичностью запускаемой программы и её выводом.
Чего здесь нет: подключения к настоящей Связке ключей, управления секретами и пользовательской
кнопки запуска. Эксперимент не включён в приложение; его место в развитии продукта —
[implementation-plan.md](implementation-plan.md).

## Сценарий и граница

В [спецификации музыкального бота](https://github.com/glockbender/svalka-muz-repostov-tgbot/blob/main/openspec/specs/local-keychain-secrets/spec.md)
сам бот один раз читает версионированную запись Связки ключей. Agent Watch не должен принимать
значения, передавать их программе или становиться универсальным посредником к хранилищу.
Спецификация также требует, чтобы ошибка доступа не содержала значения. Она не доказывает,
что произвольной новой сборке или изменённому сценарию можно передать прежнее доверие.

Учебный пример ограничен одной заранее известной нативной программой без внешних сценариев,
конфигурации и подключаемых модулей. Она связана только с системной библиотекой C; проверка
подтверждает этот список зависимостей. Встроенный учебный поставщик возвращает вымышленную
строку. Связка ключей, настоящий бот и его данные не используются.

Ни имя файла, ни подпись разработчика сами по себе не означают согласия на любую будущую
сборку. В эксперименте согласованная версия задаётся `cdhash` — идентификатором конкретного
подписанного кода, предоставленным macOS. Изменённая сборка требует другого идентификатора.
Учебные файлы подписываются без сертификата (`codesign --sign -`); личные ключи не нужны.
Обязательны параметры подписи `hard`, `kill` и `runtime`: процесс сохраняет проверяемую
целостность кода и завершается при её нарушении. Проверки подписи запрещают сетевой доступ.

## Что именно проверяется

1. На этапе согласования проверяется подпись учебного исполняемого файла и запоминается
   идентификатор этой сборки. Сценарий, символическая ссылка и неподходящий файл отклоняются.
2. `posix_spawn` создаёт процесс с `POSIX_SPAWN_START_SUSPENDED`. Рабочий каталог задан явно,
   аргументы фиксированы, окружение содержит только `PATH` и `LANG`. Вход, выход и поток ошибок
   направлены в `/dev/null`; остальные унаследованные файловые дескрипторы закрыты.
3. `SecCodeCopyGuestWithAttributes` получает ссылку на созданный процесс.
   `SecCodeCheckValidity` проверяет его динамическую идентичность по требованию к сохранённому
   `cdhash`. Проверяется выбранный ядром код, а не повторно открытый путь к файлу.
4. Только после успешной проверки процесс получает `SIGCONT`. При отказе он завершается,
   не выполняя учебную задачу. Ответ исполнителя — только `completed`, `refused` или `failed`.

В заголовке `SecCode.h` SDK Xcode 16.4 у `SecCodeCheckValidity` прямо заявлена устойчивость
проверки к изменению файлового источника кода. Проверка по пути перед запуском не обладает
таким свойством: между чтением файла и запуском по тому же пути может оказаться другой файл.

Это не изоляция от враждебного процесса с правами того же пользователя: он может вмешиваться
в процессы и файлы. Проверка идентичности также не ограничивает допустимую программу в том,
куда она сама пишет и с кем общается. Подавление стандартного вывода не защищает произвольные
файлы или сеть. Именно поэтому эксперимент допускает только известную учебную программу,
а не произвольную программу проекта, интерпретатор или сторонний модуль.

## Воспроизводимая проверка

```sh
python3 scripts/probe-trusted-program.py --scratch /path/to/isolated/scratch
```

Скрипт создаёт отдельную подпапку, собирает три маленьких нативных файла и ничего не
устанавливает. Если `--scratch` не задан, используется `AGENT_WATCH_TEST_SCRATCH`, затем
системная временная папка. Учебные файлы остаются для осмотра; каталог выводится в конце.

Проверяются первый и повторный запуск, фиксированные аргументы, окружение и рабочий каталог,
отсутствие вымышленного значения в ответе и журнале исполнителя, отказ для другой сборки,
сценария и символической ссылки. Отдельная проверка подменяет один безвредный учебный файл
другим непосредственно между предварительной проверкой пути и `posix_spawn`: заменённый
процесс отклоняется до выполнения задачи. Для проверки зависания тот же второй файл запускается
с его собственным согласованным идентификатором. Он оставляет отметку о начале работы и ждёт.
Через десять секунд внешний сценарий завершает всю группу процессов, в которой находятся
исполнитель и учебная программа. Проверка требует и отметку о запуске, и исчезновение группы.

Все проверки прошли. Учебный каталог занял 152 КБ (замер: macOS 27.2), Xcode 16.4.
Повторное разрешение macOS после обновления настоящей программы, доступ к настоящему
хранилищу и поведение сторонних зависимостей этим результатом не подтверждены. Кнопки или
обещания подключения настоящего проекта в приложении нет.
