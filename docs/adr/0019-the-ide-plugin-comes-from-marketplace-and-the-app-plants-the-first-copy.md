# Плагин IDE ставится из Marketplace, а приложение кладёт только первую копию

**Статус:** принято 2026-10-06.

JetBrains Marketplace — основной способ установки плагина. После публикации приложение ставит
плагин само, одним из двух путей:

- **IDE не запущена** — приложение распаковывает ZIP из своего бандла в `plugins/` каталога
  настроек IDE, и плагин загружается при следующем её запуске. В бандле лежит только версия, уже
  одобренная в Marketplace, — тот же подписанный ZIP.
- **IDE запущена** — приложение шлёт запрос `installPlugin` её встроенному серверу, и IDE сама
  скачивает плагин из Marketplace. Это HTTP-запрос на порт IDE, найденный через `/api/about`: у
  схемы `jetbrains://` команды установки нет. Человек подтверждает дважды — доверие к запросу и
  окно установки; в IDE, где ещё не приняли предупреждение о сторонних плагинах, — трижды.

Оба пути удаляют копии со старыми идентификаторами (`…ide`, `…plugin.jetbrains`): для IDE это
другой плагин, и Marketplace его не обновит. Установка из файла остаётся — для сборки до релиза и
для того, у кого Marketplace закрыт политикой компании.

## Почему

- **Marketplace убирает самую дорогую часть установки.** Из файла — это путь в буфере обмена, чужой
  диалог и перезапуск IDE; из Marketplace — поиск по названию на странице плагинов.
- **Обновление из файла всегда требует перезапуска, и в плагине это не исправить.**
  `PluginInstaller.installFromDisk` уходит в ветку перезапуска, как только видит уже установленную
  копию, и не спрашивает, выгружается ли она. Обновление через окно плагинов решает по
  выгружаемости, а наш плагин выгружается. Разбор с байт-кодом —
  [research/session-focus.md](../research/session-focus.md#обновление-плагина-из-файла-всегда-просит-перезапуск--так-устроена-платформа).
- **Приложению достаточно первой копии.** IDE ищет обновления плагина по его `id` и не помнит,
  откуда он поставлен, поэтому дальше копию обновляет Marketplace. Разбор —
  [research/session-focus.md](../research/session-focus.md#установка-плагина-снаружи-и-обновления-из-marketplace).

## Чем за это платим

- **Выпуски приложения и плагина связаны.** Копия новее опубликованной закрыла бы обновления, пока
  Marketplace её не догонит. Поэтому приложение везёт последнюю одобренную версию плагина, а не ту,
  что ещё на ревью.
- **В запущенную IDE файлы не кладутся.** Она не увидит копию до перезапуска, а подменять файлы уже
  загруженной копии нельзя: классы подгружаются из jar по мере надобности, и старый код смешается с
  новым.
- **Идентификатор плагина окончательный после первой загрузки.** Сменить его — значит выпустить
  другой плагин.

## Когда пересмотреть

Если JetBrains включит по умолчанию фильтр обновлений по источнику установки, копия из бандла
перестанет получать обновления, и первый путь придётся заменить вторым. Это перепроверяется с
каждым выпуском IDE.
