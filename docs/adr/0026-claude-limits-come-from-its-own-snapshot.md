# Лимиты Claude берутся из его собственного снапшота

**Статус:** принято 2026-11-24.

Проценты пятичасового и недельного окна подписки Claude и время их сброса приложение берёт из
снапшота, который Claude Code сам пишет в `~/.claude.json` под ключом `cachedUsageUtilization`.
Когда снапшот устарел, приложение само запускает Claude Code без окна с одним управляющим
запросом `get_usage` — не чаще раза в 30 минут и только пока работает сессия Claude. Интеграция
со статус-строкой снята по [ADR-0027](0027-claude-context-comes-from-the-transcript.md). Формат и
стоимость запуска описаны в [исследовании](../research/claude-plan-limits.md). Код —
`ClaudeUsageSnapshot`, `ClaudeUsageProbe` и `ClaudeUsageFeed`.

## Почему

До этого лимиты приходили только из статус-строки, а её надо подключать у каждого человека: слот у
Claude один, обычно занят своим скриптом, и обёртку поверх чужой команды люди считают неудобной и
рискованной. У большинства лимитов в виджете не было вовсе.

Других источников без настройки нет. В транскриптах и реестре сессий лимитов нет (замер: Claude
Code 2.1.326); во входных данных хуков их нет ни в документации, ни в коде Claude Code, а
`StopFailure` говорит только, что лимит кончился. Снапшот читается бесплатно — ни запуска,
ни запроса в сеть. Но обновляет его только тот, кто спрашивает сервер: `/usage`, `get_usage` или
проверка раз в сутки. Без опросчика цифре могут быть часы, поэтому нужен запасной запуск.

## Почему раз в 30 минут и только при работающей сессии

Каждый запуск — отдельная сессия Claude Code в OpenTelemetry-метриках организации:
`claude_code.session.count` растёт, хотя запроса к модели нет. Сторонняя утилита, опрашивающая так
раз в пять минут круглые сутки, давала 270 таких сессий в день на человека.

- **Только при работающей сессии Claude**: лимиты тратятся только тогда, и это то же правило «не
  опрашивать без активных сессий», что у всего приложения. Headless-запуск — чужой, в том числе
  собственный запуск приложения, — работой не считается.
- **Раз в 30 минут**: пятичасовое окно длится 300 минут, и отставание на 30 — десятая его часть.
  Виджет даёт общую картину, а момент, когда лимит кончился, приложение и так видит сразу и
  бесплатно, по хуку `StopFailure`. Получается не больше двух запусков в час рабочего времени.
- **Попытка считается, а не успех**: запуск, который ничего не вернул, держит следующий на весь
  интервал. Отказ (`get_usage` не знаком старой версии), `rate_limits_available: false` (ключ API,
  Bedrock, Vertex) и ответ, который приложение не умеет прочесть, останавливают запуски до
  перезапуска приложения: спрашивать снова бесполезно. Ответ без лимитов при
  `rate_limits_available: true` (сеть недоступна) запуски не останавливает — следующий будет в срок.
- **Свежий снапшот важнее запуска**: решение о запуске принимается после того, как файл прочитан.
  Иначе первый же проход после старта приложения, ещё не знающего никаких лимитов, запускал бы
  Claude Code даже при снапшоте двухминутной давности.

## Чем за это платим

- И ключ, и запрос не документированы; SDK называет запрос
  `usage_EXPERIMENTAL_MAY_CHANGE_DO_NOT_RELY_ON_THIS_API_YET`. Новая версия Claude Code может их
  убрать — тогда лимиты просто пропадут из виджета, а не сломают его. Проверять их нужно на каждой
  новой версии.
- До двух сессий в час в метриках организации, пока человек работает в Claude.
- Цифра бывает старой, до получаса, а если работающей сессии нет — и старше. Поэтому строка всегда
  говорит, когда цифра снята: «as of 14:05».
- Снапшот покрывает папку по умолчанию. Её лимиты видны под виджетом и в
  [`Usage profiles`](../menu-bar.md#лимиты-по-папкам-агента). У папки из `CLAUDE_CONFIG_DIR`
  могут быть другой вход и свои лимиты.

## Что отвергнуто

- **Опрос по таймеру круглые сутки**, как у сторонней утилиты: свежее, но это ровно тот шум в
  метриках, с которого исследование началось, и нарушение правила «не опрашивать без сессий».
- **Только снапшот, без запусков**: ноль сессий в метриках, но без `/usage` цифры почти всегда
  часовой давности и старше, а старая цифра с честной подписью полезна меньше свежей.
- **Статус-строка как основной источник**: свежее всего, но у тех, кто её подключил, а таких мало.
- **Запрос к эндпоинту лимитов напрямую**: нужен OAuth-токен Claude Code, а секреты чужого входа
  приложение не читает.
