# Одна дверь в состояние сессии

Событие попадает в состояние ровно одним способом — `SessionStateEngine.receive(_:)`, — и получает
в ответ одно значение `RowChange`. Пять шагов внутри идут в жёстком порядке, и порядок этот несущий:
три приватных поля переносят решения ранних шагов в последний.

Раньше шагами управлял вызывающий: пять публичных методов, которые приложение обязано было вызвать
по порядку, и поле-ответ, действительное только до следующего вызова. Порядок не был закреплён
ничем, кроме комментариев на месте вызова, а тесты вызывали последний шаг в одиночку — то есть
проверяли путь, которым приложение не ходит. При переходе один такой тест и сломался.

Подробности — `docs/architecture.md` §6, «Одна дверь в состояние».
