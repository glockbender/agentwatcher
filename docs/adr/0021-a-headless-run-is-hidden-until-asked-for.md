# Запуск без окна скрыт, пока его не попросят

**Статус:** принято 2026-10-08.

Запуск без окна — `claude -p`, запуск через Agent SDK, `codex exec` — получает строку своего вида,
`headless`, у обоих агентов ([«Запуски без окна»](../agent-processes.md#запуски-без-окна)). По
умолчанию такие строки скрыты: их нет ни в виджете, ни в меню, ни в счётчиках значка. Показывает
их переключатель `Show headless runs` на странице `General`. Скрытая строка всё равно
отслеживается и запоминается, так что включённый переключатель сразу показывает идущие запуски.

Клик по показанной строке предлагает запуск завершить, и `End` посылает его процессу `SIGTERM`
([«Запуск без окна»](../session-focus.md#запуск-без-окна)).

Категорию попросил человек 2026-10-08, а клик — «скорее всего диалог закрытия показать». Решения
ниже — что она по умолчанию скрыта, где скрыта и чем завершается запуск.

## Почему своя категория, а не `cli`

Окна у запуска нет: над ним стоит программа, которая его начала, — скрипт, тест, другой агент. Как
строка `cli`, он обещал бы терминал, которого нет, а клик поднимал бы окно этой программы. Своя
категория даёт ему своё поведение там, где оно другое: в карточке и в клике.

## Почему скрыт по умолчанию

- **Его начинает программа, а не человек.** На этой машине 22 запуска `codex exec`: из временных
  каталогов сессий Claude, проб, прогонов тестов и проверки производительности, и один — от самого
  Codex Desktop. Сессия, которая начала запуск, обычно уже стоит в виджете и сама говорит «работает».
- **Его вопрос уходит программе, а не человеку.** `claude -p` отменяет вопрос MCP-сервера сразу
  (замер: Claude Code 2.1.293), а `codex exec` на этой машине работал с `approval: never` (замер:
  Codex 0.153.4). То, ради чего виджет существует, — показать ожидание человека, — у запуска почти не
  бывает.

Включить стоит тому, кто сам запускает долгие задачи через `claude -p` или `codex exec` и хочет за
ними следить.

## Почему клик спрашивает и почему `SIGTERM`

Поднимать нечего, а единственное, что клик может сделать для запуска, — его завершить. Это второй
клик в виджете, который что-то заканчивает, поэтому он, как и первый
([ADR-0013](0013-a-click-ends-an-agent-its-closed-terminal-left-behind.md)), сначала спрашивает.

`SIGTERM` — обычная просьба завершиться, и Claude Code отвечает на неё своим обычным выходом с
`SessionEnd` (замер: Claude Code 2.1.293). `SIGINT` вёл себя так же, но у `codex exec` его действие
не замерено, а `SIGTERM` завершает и программу, которая его не обрабатывает. Строка ответа агента не
ждёт: за выходом процесса запуска приложение следит само.

## Отвергнуто

- **Отбрасывать запуски в отправителе.** Тогда включённый переключатель не показал бы ни одного
  идущего запуска, а только те, что начнутся после.
- **Переключатель на каждого агента.** Причина скрывать одна и та же у обоих, а два переключателя —
  два места, где её надо помнить.
