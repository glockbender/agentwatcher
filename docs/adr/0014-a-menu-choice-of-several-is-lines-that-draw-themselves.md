# Выбор нескольких пунктов в меню — строки, которые рисуют себя сами

**Статус:** частично заменено [ADR-0016](0016-every-setting-lives-in-one-window.md) — подменю с переключателями убраны из меню.

Уточнено [ADR-0018](0018-the-menus-sessions-are-one-scrolling-list.md): приём — пункт меню со своим
`view` — живёт в списке сессий, внутри которого стоит и строка сломанной сессии
([ADR-0013](0013-a-click-ends-an-agent-its-closed-terminal-left-behind.md), «Клик спрашивает»); про
стрелки раздел «Клавиатура» ниже уточнён замером 2026-10-02.

Подменю `Settings ▸ Sessions in Menu` — первое место в меню, где выбирают несколько пунктов
сразу: общий переключатель и по строке на группу сессий. Второе такое — `Settings ▸ Menu Bar Icon`
(«Второе такое подменю» ниже). Каждая строка обоих — пункт меню со своим `view`
(`MenuToggleRowView`). Клик по ней не закрывает меню, клавиатура доходит до неё самой, а
подсветку, галочку и серый вид она рисует сама.

Решение неочевидное: у каждой такой строки своё рисование и своя обработка клавиш, хотя меню
умеет всё это для обычных пунктов. Ниже — почему иначе не получилось.

## Почему не обычные пункты

Обычный пункт меню закрывает меню при выборе, и флага, который это отменяет, у пункта нет. Отметить
три группы значило бы три раза открыть меню и дважды спуститься по подменю. Проба на macOS 15.3.1
проверила два варианта рядом:

- обычные пункты с `NSMenu.selectionMode = .selectAny` — меню закрывалось на каждом выборе:
  `selectionMode` управляет только галочками (замер: macOS 15.3.1);
- пункты со своим `view` — две строки отмечены подряд, и ни подменю, ни меню над ним не закрылись
  (замер: macOS 15.3.1).
  Верх меню при этом можно перестраивать: строки сессий меняются, пока курсор ещё в подменю.

## Почему не окно

Окно было первым предложением: несколько галочек сразу — естественная задача для окна. Владелец
выбрал иерархическое меню: настройки на уровень ниже, строки сессий наверху, и выбор групп там же, где
его результат. Окно остаётся для того, что меню показать не может, — лампы, где у каждой из
одиннадцати фаз четыре настройки (цвет, движение, второй цвет, полный цикл — 44 выбора), и
порядка строк, который виден только в движущемся списке.

## Клавиатура

Первая версия оставила у пункта обычное действие «для клавиатуры». Вторая проба показала, что так не
бывает:

- на Return меню действие пункта со своим `view` не вызывает никогда (замер: macOS 15.3.1);
- локальный перехватчик клавиш (`addLocalMonitorForEvents`) нажатий не видит (замер: macOS 15.3.1);
- `keyDown` подсвеченной строки получает пробел и Return, но только если её `view` принимает
  клавиши (`acceptsFirstResponder`). Без этого Return и пробел не делали ничего (замер: macOS
  15.3.1).

Поэтому строка принимает клавиши, выбирает себя на Return, пробел и Enter цифровой клавиатуры, а
остальные клавиши отдаёт меню. Стрелки остаются стрелками macOS: по смыслу, а не по положению на
экране. В подменю, открывшемся слева, ← закрывает его — так же, как в обычном подменю (замер: macOS
15.3.1).

Уточнено 2026-10-02 пробой с записью каждого нажатия
([ADR-0018](0018-the-menus-sessions-are-one-scrolling-list.md), «Что замерено»): стрелки строка
получает не все. Меню оставляет себе каждую стрелку, которой может воспользоваться, — ↑ и ↓, если в
ту сторону есть пункт, — и отдаёт строке только ту, с которой ему делать нечего: ↑ на первом пункте,
→ на строке без подменю (замер: macOS 15.3.1). Стрелки работали как обычно не потому, что строка
отдавала их меню, а
потому, что меню их и не отдавало.

## Чем за это платим

- Рисование: подсветка, галочка и серый вид — свои, в системных цветах. Если macOS сменит вид меню,
  эти строки сами не изменятся.
- Доступность: строка сама называет себя флажком для программ чтения с экрана и сама отвечает на
  нажатие через Accessibility.
- Проверка: что меню не закрывается, тест проверить не может — только проба с настоящим кликом.
  Устройство — в
  [«Сессии в меню»](../menu-bar.md#сессии-в-меню).

Обычные строки меню остаются обычными. Свои строки — только там, где выбирают несколько пунктов
сразу; строки, которые меню закрывают, и строки, которые его не закрывают, в одном подменю не
смешиваются.

## Второе такое подменю

Дополнено 2026-09-28. `Settings ▸ Menu Bar Icon` выбирает несколько состояний значка, а над ними —
один вид значка из двух (`Sphere`, `Counts`). Одиночный выбор обычные строки умеют, но строки
вида всё равно свои: иначе в одном подменю смешались бы строки, которые меню закрывают, и строки, которые не закрывают. Для
программ чтения с экрана они называют себя переключателем (radio button), а не флажком.
