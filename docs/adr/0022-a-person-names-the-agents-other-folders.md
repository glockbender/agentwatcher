# Другие папки агентов называет человек

**Статус:** принято 2026-10-09.

Агент, запущенный с `CODEX_HOME` или `CLAUDE_CONFIG_DIR`, читает хуки только из этой папки
(замер: Codex 0.153.4, 0.161.0) (замер: Claude Code 2.1.294). Хуки Agent Watch из `~/.codex` и
`~/.claude` до него не доходят, и его сессий в виджете нет. Поэтому у каждого агента есть список
других папок: человек добавляет их на странице `Tooling`, приложение ставит в каждую свои хуки и
ищет в каждой транскрипты и записи процессов Claude
([«Другие папки агента»](../agent-install.md#другие-папки-агента)).

Запрос пришёл 2026-10-08: у одного человека три окружения Codex (`~/.codex`, `~/.codex-work`,
`~/.codex-personal`), и он переключает их алиасами; у другого `direnv` ставит `CODEX_HOME` по папке
проекта. Решения ниже: откуда приложение знает папки, как событие говорит, из какой оно папки, и
чего в другой папке нет.

## Почему список, а не поиск

- **Папка может лежать где угодно.** С `direnv` она лежит рядом с проектом, а не рядом с
  `~/.codex`. Поиск по `~/.codex-*` нашёл бы только тех, кто называет папки так же.
- **Найденная папка — ещё не согласие.** Установка пишет в чужую конфигурацию. В папку, которую
  человек не называл, приложение не пишет, как не трогает и чужие хуки.
- **У приложения нет окружения агента.** Его запускают из Finder, и `CODEX_HOME` у него нет.
  Переменную видит только отправитель, а он запускается, когда хуки в папке уже стоят.

## Почему по сокету идёт ярлык папки, а не путь

Подтверждение хуков Codex хранит для каждого файла хуков отдельно: ключ доверия начинается с пути к
`hooks.json` ([«Доверие к хукам у Codex»](../agent-install.md#доверие-к-хукам-у-codex)). Значит, и
«события доходят» нужно помнить по папке, а для этого отправитель должен сказать, из какой папки
пришло событие.

Путь по сокету не идёт ([ADR-0001](0001-nothing-leading-to-a-file-crosses-the-socket.md)).
Отправитель посылает ярлык папки: ту же хеш-метку, что у идентификатора сессии, от канонического
пути (ссылки раскрыты, `/tmp` и `/private/tmp` — одна папка). Приложение сравнивает ярлык с
ярлыками своих папок и ничего по нему не открывает. Строку не той формы оно отбрасывает, и событие
тогда считается событием из папки по умолчанию.

Папку отправитель берёт из `transcript_path`: это сам агент говорит, куда пишет. Без него — из
переменной окружения, а без переменной это папка по умолчанию.

## Статус-строка — только в папке по умолчанию

Статус-строка Claude подключается только в `~/.claude/settings.json`. Обёртка хранит одну команду
человека, и для каждой папки понадобились бы своя обёртка и своя копия команды. У сессии из другой
папки поэтому нет процента контекста и расхода квот. Это решение об объёме работы, а не
невозможность: открытый пункт — в [плане](../implementation-plan.md#открытые-решения).

## Отвергнуто

- **Путь в поле запроса.** См. выше.
- **Поиск папок** по `~/.codex-*`, по процессам агентов или по настройкам `direnv`. См.
  «Почему список, а не поиск».
- **Записать доверие Codex в каждую папку самим.** По той же причине, что и для папки по умолчанию:
  подделать хеш доверия значит обойти механизм, который ради этого и существует.
