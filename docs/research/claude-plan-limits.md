# Лимиты плана Claude через запуск `claude`

> **Архив.** Исследование закрыто 2026-11-20. Что из него осталось решить, записано в
> [плане реализации](../implementation-plan.md#открытые-решения). Текст больше не обновляется:
> факты в нём верны на дату и версию замера (Claude Code 2.1.326, macOS 27.2).

## Задача

Сторонняя утилита строки меню (Vorssaint 3.4.4) показывает лимиты подписки Claude: процент
пятичасового окна, недельного окна и время их сброса. Для этого она круглые сутки запускает
`claude` без окна, примерно раз в пять минут. Каждый такой запуск — сессия Claude Code в
OpenTelemetry-метриках организации, хотя ни одного запроса к модели в нём нет.

Вопрос: как устроен этот приём, что он даёт и стоит ли Agent Watch брать его как источник
сведений о лимитах.

Короткий ответ: **по таймеру — нет.** Agent Watch уже получает те же проценты бесплатно из
статус-строки Claude, а запуск по таймеру нарушает правило «не опрашивать, пока нет активных
сессий» и раздувает счётчик сессий организации. Допустим запуск по явному действию человека, не
чаще раза в пять минут.

## Механизм

Vorssaint запускает (видно в `ps`):

```sh
claude --print --input-format stream-json --output-format stream-json --verbose \
  --no-session-persistence --tools "" --strict-mcp-config --mcp-config '{"mcpServers":{}}' \
  --setting-sources "" --settings '{"disableAllHooks":true}'
```

- `--input-format stream-json` — stdin принимает JSON-строки, в том числе управляющие сообщения
  (control protocol: запрос `control_request`, ответ `control_response` с тем же `request_id`).
- `--no-session-persistence` — транскрипт не пишется, сессию нельзя продолжить.
- `--tools ""`, `--strict-mcp-config` с пустым списком, `--setting-sources ""` и
  `disableAllHooks` — без инструментов, MCP-серверов, чужих настроек и хуков: запуск не тянет за
  собой ничего из окружения человека.

В stdin уходит одна строка, запрос `get_usage`:

```json
{"type":"control_request","request_id":"<uuid>","request":{"subtype":"get_usage","skip_behaviors":true}}
```

Затем утилита читает stdout до `control_response` с тем же `request_id` и закрывает stdin; процесс
выходит сам с кодом 0. Сообщение `initialize` перед ним не нужно (замер: Claude Code 2.1.326).

За двадцать минут выборки Vorssaint запускал `claude` пять раз, раз в 5–5,5 минуты, напрямую
от своего процесса. Каждый запуск жил около двух секунд и каждый раз обновлял снапшот лимитов
(о нём ниже), то есть каждый раз спрашивал сервер. Это 11–12 запусков в час круглые сутки.

Что Vorssaint шлёт именно это, выведено, а не подсмотрено: stdin чужого процесса без обёртки над
`claude` не увидеть, а короткие строки Swift хранит в коде, и `strings` их не находит. В бинарнике
утилиты есть поля, которые бывают только в ответе `get_usage` (`rate_limits_available`,
`five_hour`, `seven_day`, `resets_at`), и фраза «No prompt is sent». Запрос выше воспроизводит
ответ целиком.

### Откуда `claude` берёт цифры

Из бинарника Claude Code 2.1.326 (прочитано, не замерено):

- Обработчик `get_usage` спрашивает `GET /api/oauth/usage` с OAuth-токеном самого `claude`. Токен
  наружу не выходит: утилита его не видит.
- Ответ эндпоинта кладётся в `~/.claude.json`, ключ `cachedUsageUtilization`, с `fetchedAtMs` и
  `accountUuid`. Пока снапшоту меньше 60 секунд, следующий `get_usage` из любого процесса
  отвечает из него и эндпоинт не спрашивает. Снапшот старше часа не используется вовсе.
- Пишут снапшот только три места: `/usage`, `get_usage` и редкая проверка промо-кредитов по
  таймеру. Интерактивная сессия сама его не обновляет, поэтому свежим он бывает только тогда, когда
  кто-то опрашивает. На этой машине это и есть Vorssaint.
- Ответ 429 или 403 от эндпоинта запоминается для этого токена на `retry-after`, а без него на
  5 минут, но не дольше часа. Общая ли это память для всех процессов или только для одного,
  из бинарника не понять.

В SDK этот запрос называется `usage_EXPERIMENTAL_MAY_CHANGE_DO_NOT_RELY_ON_THIS_API_YET`, а схема
ответа помечена «Experimental — the response shape may change».

## Что приходит в ответе

Замер: Claude Code 2.1.326, подписка claude.ai.

- `session` — расходы самого запуска: `total_cost_usd: 0`, `total_api_duration_ms: 0`,
  `model_usage: {}`. Это и доказывает, что запрос к модели не уходил.
- `subscription_type` — тип подписки (`pro`, `max`, `team`, `enterprise`), `null` для ключа API и
  сторонних провайдеров.
- `rate_limits_available` — `false` для ключа API, Bedrock, Vertex или токена без нужного scope;
  тогда `rate_limits` равен `null`.
- `rate_limits.five_hour` и `rate_limits.seven_day` — `utilization` (процент, 0–100) и
  `resets_at` (ISO 8601).
- `rate_limits.seven_day_opus`, `seven_day_sonnet`, `seven_day_oauth_apps` — у этого аккаунта
  `null`.
- `rate_limits.model_scoped` — недельные окна отдельных моделей (`display_name`, `utilization`,
  `resets_at`).
- `rate_limits.extra_usage` и `rate_limits.spend` — платное продолжение сверх лимита: включено ли,
  потолок, потрачено.
- `rate_limits.limits` — те же окна списком, как их отдаёт сервер (`kind`: `session`,
  `weekly_all`, `weekly_scoped`; `percent`, `severity`, `is_active`).
- Ещё два десятка полей с кодовыми именами (`cinder_cove`, `amber_gauge`, …) — у этого аккаунта
  все `null`. Ответ эндпоинта пробрасывается почти как есть, и это лишний повод не полагаться на
  его форму.
- `behaviors` — `null` при `skip_behaviors: true`. Без флага `claude` сканирует все транскрипты
  за семь дней, чтобы сказать, на что ушли лимиты, — для счётчика это лишняя работа.

## Цена одного запуска

Замер: Claude Code 2.1.326, три запуска.

- **Токены и деньги: ноль.** Ни `assistant`, ни `result` в stdout, `total_cost_usd: 0`.
- **Время:** ответ через 0,85–1,1 секунды после старта, выход через 1,8 секунды.
- **Файлы:** ни ключей в `~/.claude.json`, ни записи в `~/.claude/sessions` не прибавилось.
  Снапшот лимитов перезаписывается, если он был старше 60 секунд.
- **Сеть, даже без запроса к модели** (по `--debug-file`): remote managed settings, GrowthBook,
  список MCP-серверов claude.ai (несмотря на `--strict-mcp-config`), пакет `event_logging` в
  Anthropic, инициализация OpenTelemetry-экспорта, если он настроен, и `GET /api/oauth/usage`,
  если снапшот устарел.
- **Телеметрия:** каждый запуск — это `claude_code.session.count` +1 с `start_type=fresh`
  и entrypoint `sdk-cli`. Документация признаёт, что сессия без промпта увеличивает счётчик, не
  добавляя активного пользователя. При запуске раз в пять минут это около 270 «пустых» сессий в
  сутки на человека.
- **Процессор:** каждый раз стартует бинарник в 350 МБ.

## Что из этого официально

По документации Claude Code (code.claude.com/docs, проверено 2026-11-20):

| Что | Статус |
|---|---|
| `rate_limits` во входе статус-строки (`five_hour`/`seven_day`: `used_percentage`, `resets_at`) | документировано, раздел «Rate limit usage» страницы statusline |
| `RateLimitEvent` / `SDKRateLimitEvent` в потоке SDK | документировано; приходит только по ходу запросов к модели |
| Управляющие сообщения stream-json как протокол | не описаны: на конверт `control_request` ссылки есть, списка подтипов нет |
| `get_usage` | не документирован; в SDK — `…_EXPERIMENTAL_MAY_CHANGE_DO_NOT_RELY_ON_THIS_API_YET` |
| `cachedUsageUtilization` в `~/.claude.json` | внутренний кэш, не документирован |
| `/api/oauth/usage` напрямую | внутренний эндпоинт; требует OAuth-токен, который приложению читать нельзя |

## Что уже есть в Agent Watch

Agent Watch подключает свою обёртку статус-строки Claude
([«Claude: статус-строка»](../agent-install.md#claude-статус-строка)) и уже берёт из неё
`rate_limits.five_hour.used_percentage` и `rate_limits.seven_day.used_percentage`; виджет пишет
их как «5h 21% · 7d 3%». Время сброса (`resets_at`) из того же пейлоада отбрасывается
сознательно, потому что его никто не показывает
([«Приватность и безопасность»](../architecture.md#приватность-и-безопасность)).

Статус-строка обновляется по ходу работы сессии, то есть ровно тогда, когда лимиты и меняются.
Сервер считает использование по аккаунту целиком, поэтому проценты включают и работу на других
машинах — но узнаёт о ней приложение только со следующим ответом модели в своей сессии.

Значит, `get_usage` добавил бы к уже имеющемуся только три вещи:

1. свежие цифры, когда на этом Mac не идёт ни одна сессия (например, после работы на другой
   машине или в claude.ai);
2. окна отдельных моделей и платное продолжение;
3. ответ «лимитов у этого входа нет» (`rate_limits_available: false`).

## Рекомендация

1. **Не запускать `claude` по таймеру.** Правило «не опрашивать, пока нет активных сессий»
   ([AGENTS.md](../../AGENTS.md)) прямо запрещает приём Vorssaint, а каждая сессия в метриках
   организации — шум для тех, кто их читает.
2. **Основной источник — статус-строка.** Она документирована, бесплатна и уже подключена. Самое
   дешёвое улучшение — перестать отбрасывать `resets_at`: тогда виджет может написать «сброс в
   22:30» и сам обнулить пятичасовое окно, когда его время прошло, без единого запуска. Это
   меняет решение в «Приватности и безопасности», поэтому вынесено в открытые решения плана.
3. **`get_usage` — только по явному действию человека**, если до этого дойдёт: например, кнопка
   «Обновить лимиты» в меню, когда нет живых сессий. Не чаще раза в пять минут: это и больше
   60-секундного окна снапшота, и равно сроку, на который `claude` запоминает 429.
4. **Если запускать, то так:**
   - флаги как у Vorssaint и `skip_behaviors: true`;
   - одна строка `control_request`, чтение stdout до `control_response` с тем же `request_id`,
     затем закрыть stdin — процесс выйдет сам;
   - жёсткий таймаут 10 секунд, после него `SIGTERM`, затем `SIGKILL`;
   - `rate_limits_available: false`, ошибка или незнакомая форма ответа — молча показать то,
     что пришло из статус-строки (fail-open);
   - запускать из `AgentWatchLookup`: он спрашивает машину и отвечает.
5. **Не читать `cachedUsageUtilization` из `~/.claude.json`.** Запусков он не стоит, но это
   внутренний кэш без обещаний о форме, и свежий он только пока кто-то опрашивает. Без такого
   опросчика он устаревает за минуты, и приложение показывало бы старые цифры как новые.

## Как это было проверено

- `strings` по бинарнику Vorssaint 3.4.4 и по бинарнику Claude Code 2.1.326: обработчик
  `get_usage`, схема ответа, кэш снапшота и его сроки.
- Выборка `ps` раз в полсекунды двадцать минут: время жизни запусков Vorssaint и момент, когда
  меняется `fetchedAtMs` снапшота.
- Три собственных запуска с теми же флагами, из пустого каталога, с окружением из `HOME`, `PATH`
  и `USER`. Первый сходил за лимитами в сеть (снапшот был старше 60 секунд и обновился), два
  других ответили из снапшота. В третьем был `--debug-file`, из него — список сетевых обращений.
- Ни токены, ни Keychain, ни cookies не читались.
