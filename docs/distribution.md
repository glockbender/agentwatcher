# Дистрибуция

## Требования

Исходные заметки, дословно. Ниже — что из них закрыто и как устроено то, что уже есть.

- дистрибуция пока только через сбор установочного пакета и его публикация инструментами гитхаба
  - при этом надо придумать как сделать проверку обновлений
    - при появлении новой версии, при запуске тула всегда просить обновиться с возможностью отказаться от обновления
- нужно четко выделить логику первого запуска
  - окно всегда по центру основного экрана, т.к. оно мелкое и легко его не найти, еще не освоившись с тулом
  - нужно встроить установку в агентские тулы в самом приложении. 
    - Тул пока должен нести с собой плагин с актуальными скриптами хуков и всей необходимой интеграцией. 
    - При явной проверке установленных тулов в первый запуск 
      - проверка должна выполняться вообще при каждом новом запуске тула, не только при первом
      - попросить пользователя сначала установить необходимую обвязку. 
        - для каждого тула явно предлагать согласиться на установку
        - если это не первый запуск, но проверка показала новый установленный тул, показать список установленных и неустановленных и дать явно установить. 
        - запомнить выбор, и триггернуть его еще раз только при появлении новго тула. 
        - при этом в меню должна быть эта настройка, если вдруг выбор захочется изменить

## Что из этого закрыто

- **Сбор пакета и публикация средствами GitHub** — сделано, устройство ниже.
- **Установка интеграций внутри приложения** — сделана окном тулинга: hooks и статус-строка для

## Что такое релиз

Тег `vX.Y.Z` запускает `.github/workflows/release.yml`, и тот оставляет **черновик** релиза с двумя
файлами:

- `AgentWatch-<версия>.zip` — бандл приложения, упакованный `ditto`. Это единственный архиватор,
  сохраняющий символические ссылки и расширенные атрибуты бандла, а с ними и подпись: замерено —
  после распаковки `codesign --verify` проходит;
- `AgentWatch-<версия>.zip.sha256` — контрольная сумма в формате, который понимает `shasum -c`.

Черновик, а не публикация: что написано в примечаниях и увидит ли это мир — решение человека.

Локально то же делает `task release` (`scripts/release.sh`): собирает бандл в release-конфигурации,
кладёт zip и сумму в `dist/` и печатает, чем подписал.

## Версия

Единственный источник — `CFBundleShortVersionString` в `Resources/Info.plist`. Из него же при сборке
бандла пишется `CFBundleVersion`: по нему macOS решает, какая из двух копий новее, и константа в нём
делает все сборки одинаковыми на вид — а будущей проверке обновлений сравнивать было бы нечего.

Workflow первым делом сверяет тег с этим значением и падает при расхождении, ничего не собрав.
Релиз, у которого имя файла и окно «О программе» говорят разное, находит только тот, кто его скачал.

## Подпись: где мы сейчас

Релиз подписан **ad-hoc** — подписью без сертификата. Что это значит, замерено:

```
spctl --assess --type execute  →  rejected
```

Gatekeeper отвергает такой бандл независимо от карантина: он смотрит на подпись, а флаг
`com.apple.quarantine` решает другое — будет ли вообще проверка при первом запуске. Поэтому рабочая
инструкция для скачавшего одна:

```sh
xattr -dr com.apple.quarantine /Applications/AgentWatch.app
```

Обход через Finder («Control-click → Open») в macOS 15 убран; остался путь через
System Settings → Privacy & Security → Open Anyway, и для приложений без Developer ID он срабатывает
не у всех. Команда выше работает всегда — проверено: после неё из атрибутов остаётся только
`com.apple.provenance`, который macOS ставит себе сама.

Сертификат `Agent Watch Developer` из `scripts/build-app.sh` в релиз **не идёт**. Он самоподписанный
и нужен для другого — чтобы macOS не теряла выданные разрешения при каждой пересборке (разбор — в
комментарии самого скрипта, как его завести — в `AGENTS.md`). Скачавшему он не говорит ничего, поэтому `release.sh` берёт только идентичность, названную
явно в `AGENT_WATCH_RELEASE_IDENTITY`, а иначе подписывает ad-hoc и предупреждает об этом.

## Что нужно для нотаризации

Нотаризация (Apple проверяет бандл у себя и ставит отметку, после которой macOS открывает его молча)
— это связка из четырёх вещей, и она упирается в платную Apple Developer Program:

1. сертификат **Developer ID Application** — выдаётся только участнику программы (99 USD в год);
2. **hardened runtime** (`codesign --options runtime`) — без него бандл на нотаризацию не принимают;
3. **entitlement** `com.apple.security.automation.apple-events` — hardened runtime запрещает Apple
   Events, а на них держится переход к вкладке терминала (`NSAppleEventsUsageDescription` в
   `Info.plist` ровно про это). Без entitlement функция молча перестанет работать, поэтому hardened
   runtime включается вместе с нотаризацией, а не раньше;
4. `xcrun notarytool submit --wait` с учётными данными в keychain-профиле
   (`notarytool store-credentials`), затем `xcrun stapler staple` — отметка прикрепляется к бандлу,
   чтобы он открывался и без сети.

Пока сертификата нет, этот код нечем проверить, поэтому его нет и в `release.sh`.

## Плагин IDE в релизе

Плагин версионируется отдельно от приложения и в бандл не вкладывается (разбор — в
[плане](implementation-plan.md)). В релиз он попадает отдельным файлом, и **имя файла — контракт**:
`agent-watch-ide-<версия>.zip`. Его разбирает `IDEPluginInstallation.stagedPlugin`, когда решает,
какой файл предлагать IDE, и по нему же сравнивает версии.

CI его не собирает: сборка идёт против IDE, установленной на машине (`local(ideHome)` в
`ide-plugin/build.gradle.kts`), а качать дистрибутив IDE в CI — гигабайт ради файла, который
собирается локально одной командой:

```sh
task plugin
gh release upload vX.Y.Z ide-plugin/build/distributions/agent-watch-ide-<версия>.zip
```

Файл берётся из каталога сборки, а не из staging-каталога приложения: в релиз должен уехать тот
файл, который только что собран, а не тот, что там лежал.

## Чего ещё нет

- **Скачивания файла плагина из приложения.** Читающая сторона уже есть — каталог
  `~/Library/Application Support/AgentWatch/ide-plugin/`, — и адрес теперь тоже: плагин лежит в
  релизе рядом с приложением. Не хватает только кнопки, которая скачает его туда.
- **Образа для первой установки (`.dmg`)** — того самого окна с иконкой приложения и стрелкой на
  папку Applications. Пока раздаётся `.zip`. Обновление образ не использует и не будет: монтировать
  том ради замены бандла незачем.
- **Нотаризации** — см. выше.
- **Первого запуска как отдельного сценария** — требования в заметках выше, разбор по шагам в
  [плане](implementation-plan.md), этап 3.
