# План первого полноценного релиза

Здесь всё, что осталось до первого стабильного релиза, и условия, при которых каждый шаг считается
сделанным. Это единственный такой список; после выпуска документ уходит. Чего здесь нет: этапы
дальше релиза и открытые продуктовые решения — в [плане реализации](implementation-plan.md); как
собирается и подписывается релиз — в [distribution.md](distribution.md).

## Что уже есть

- Детерминированный мониторинг Claude Code и Codex, виджет, меню сессий, настройки оформления,
  порядка и сочетания клавиш, сохранение истории, переход к сессии, самообновление.
- Установка и снятие интеграций из Tooling; сохранение чужих хуков и статусной команды.
- Новый мастер: выбор агента → подключение → проверка сигнала; доступ с пустого виджета и
  `Tooling → Set Up Again…`. Повторение ничего не удаляет. Внешний вид и сессии сохраняются.
- Признаки найденной программы отдельно от состояния подключения. Ошибки записи видны в окне.
- README с настоящими AppKit-изображениями на вымышленных данных и короткой GIF-демонстрацией.
- Плагин IDE: classic/reworked terminal, ping, тесты, verifier, CI подписи и публикации.

Это готовность отдельных частей, а не заявление о проверенной чистой установке всего продукта.

## Порядок работ и критерии завершения

### 1. Отправить текущий плагин на первое ревью Marketplace

- [ ] Решить окончательный bundle identifier: сейчас `com.glockbender.agentwatch` и у приложения, и у
  плагина. После первой загрузки идентификатор плагина не меняется.
- [x] `task plugin-verify`: для текущего 0.1.4 подтверждены кэшированные результаты `Compatible`
  на 251.23774.430 и 261.26222.72. После изменений плагина проверка повторяется.
- [ ] Проверить в живой GoLand и IntelliJ IDEA оба терминала: две вкладки одного проекта,
  два проекта, закрытая вкладка, отсутствие агента, `Check`, отключение и повторное включение плагина.
- [ ] Проверить GoLand и IntelliJ IDEA, установленные без Toolbox, на чистом профиле macOS, где
  Toolbox никогда не стоял, — для платформы 2025.1 и текущей поддерживаемой версии. Проверить
  установку фоновой службы (daemon) `jetbrainsd`, регистрацию адреса, `Check` плагина и фокус
  нужной вкладки терминала. Успех Plugin Verifier этот путь доставки не доказывает.
  Локальная GoLand 2026.1.4 несёт `platform-daemon-plugin/jetbrainsd_mac_aarch64.tar.gz`, и
  [JetBrains описывает распаковку и запуск службы самой IDE](https://www.jetbrains.com/help/go/jetbrainsd.html),
  но сценарий чистого профиля не проверен. Если самая старая поддерживаемая IDE службу не
  приносит, надо решить доставку или поднять минимальную версию — до того, как обещать работу
  без Toolbox.
- [ ] Запустить `publish-plugin.yml` вручную и получить подписанный **0.1.4** ZIP.
- [ ] Владелец аккаунта подтверждает профиль, контакты и статус вендора, принимает соглашение
  и загружает первую версию. Текущий статус кабинета нельзя вывести из отсутствия токена GitHub.
- [ ] Добавить скриншоты и краткую демонстрацию перехода к вкладке на страницу плагина.
- [ ] После одобрения сохранить `PUBLISH_TOKEN`, ссылку/ID Marketplace и проверить следующую
  публикацию через `plugin-vX.Y.Z`.
- [ ] После одобрения научить приложение ставить плагин самому. Приложение ставит только первую
  копию, обновляет её Marketplace ([ADR-0019](adr/0019-the-ide-plugin-comes-from-marketplace-and-the-app-plants-the-first-copy.md)):
  - [ ] незапущенная IDE: бандл приложения везёт последнюю одобренную версию — тот же подписанный
    ZIP, — и приложение распаковывает её в `plugins/`; плагин загрузится при следующем запуске IDE;
  - [ ] запущенная IDE: запрос `installPlugin` к её встроенному серверу; IDE ставит плагин из
    Marketplace после двух подтверждений человека;
  - [ ] оба пути удаляют копии со старыми ID;
  - [ ] закрыть три замера из [исследования](research/session-focus.md#что-осталось-померить):
    обновление копии, положенной снаружи, повтор вопроса о доверии, установка нашего плагина без
    перезапуска.

Готово, когда новый пользователь находит плагин в IDE, ставит его, получает ответ `Check` и попадает
в нужную вкладку. Первая загрузка и проверка каждой версии описаны в
[официальной инструкции JetBrains](https://plugins.jetbrains.com/docs/marketplace/uploading-a-new-plugin.html)
и [правилах одобрения](https://plugins.jetbrains.com/docs/marketplace/jetbrains-marketplace-approval-guidelines.html).
Подробный порядок подписи — [distribution.md](distribution.md#плагин-ide-в-marketplace).

### 2. Довести установку приложения до обычного macOS-сценария

- [ ] Решить вопрос Apple Developer Program и сертификата Developer ID Application.
- [ ] После получения сертификата добавить в CI подпись, hardened runtime, entitlement Apple Events,
  notarization и stapling; проверить Ghostty/JetBrains после включения ограничений.
- [x] Собрать `.dmg` со ссылкой на Applications; ZIP остаётся для самообновления.
- [ ] Решить по проверке на чистом профиле, нужно ли оформить окно образа: фон со стрелкой,
  расставленные значки.
- [ ] Проверить скачивание браузером, Gatekeeper и первый запуск на чистом macOS-профиле.

Готово, когда установка не требует `xattr` или ручного редактирования конфигурации.
Требования к подписи и hardened runtime — [Apple: Developer ID](https://developer.apple.com/developer-id/).
Без этого можно продолжать alpha; для обещанного простого публичного релиза это блокер.

### 3. Закрыть путь «скачал → увидел свою сессию»

- [x] Понятный вход с пустого виджета, выделенный текущий шаг, объяснение подключения.
- [x] Повторный онбординг без сброса данных; явная установка вместо автоматической записи.
- [x] Наличие исполняемого файла отдельно от установленной интеграции и полученного события.
- [x] Инструкция Codex trust-step и проверка доставки по настоящему событию.
- [ ] Проверить мастер на чистом профиле: только Claude, только Codex, оба, ни одного, нестандартный
  PATH, недоступная конфигурация, отмена и повторное открытие, уже установленные хуки.
- [ ] Проверить текущие версии агентов: действительно ли показанные шаги доверия/reload соответствуют UI.
  Полученное событие подтверждает доставку, но не доказывает доверие ко **всем** определениям хуков.
- [ ] Проверить первое открытие с уже работающими обнаруженными сессиями: кнопка пустого виджета
  тогда не видна, вход остаётся через Tooling. Решить по проверке, нужен ли отдельный баннер.
- [ ] Закрыть сценарий нового агента после первой настройки: сейчас наличие перечитывается при
  открытии Tooling, автоматического предложения о новой установке и памяти отказа нет.
- [ ] Плагин ставит само приложение — последний пункт раздела 1. До этого `Open Plugins` требует
  заранее помещённого ZIP, а установка из IDE вручную работает.

### 4. Проверить релизную матрицу

- [ ] Apple Silicon: macOS 14 и актуальная поддерживаемая версия; светлая/тёмная тема,
  увеличенный текст/масштаб, небольшой экран, VoiceOver, Reduce Motion; на macOS 14 — что значок
  в строке меню находит свои четыре символа SF (замер был на 15.3.1, без них значок остаётся
  прежним).
- [ ] Клавиатура в вопросе о завершении агента, заданном в меню; разделённые панели Ghostty и
  вкладка `claude attach` в правиле трёх условий; стекло на экране macOS 26.
- [ ] Сфера и сетка из трёх состояний в настоящей строке меню на тёплых обоях: проба рисует голый
  градиент, а он хуже настоящей панели.
- [ ] Claude и Codex: start, work, approval, choice, plan, subagent, background, limit, complete,
  закрытие терминала, перезапуск приложения. Версии и наблюдения записать в measurements.md.
- [ ] Hooks: установка, повторная установка, repair, removal; чужие записи и статусная команда сохраняются.
- [ ] Приложение выключено / socket недоступен: агент продолжает работу, отправитель завершается быстро.
- [ ] Обновление из опубликованного alpha в кандидат: настройки, история, разрешения и sender-ссылка
  остаются рабочими; отмена и сетевой сбой не ломают текущую копию.
- [ ] `task verify-all` на окончательном коммите; `task plugin-verify` на окончательном ZIP.

### 5. Подготовить и опубликовать стабильный выпуск

- [ ] Черновик `v0.2.0` собран до последних изменений: выпустить кандидат с версией выше 0.2.0 или

- [ ] Обновить release notes и изображения по окончательному интерфейсу. README здесь отдельного

- [ ] Выпустить draft, приложить тот же подписанный plugin ZIP, который проверен/отправлен в Marketplace,
  ZIP приложения с checksum и DMG; проверить скачанные файлы.
- [ ] После приёмки опубликовать **стабильный** release и проверить `/releases/latest` и обновление
  с предыдущей установленной версии. Тег и draft сами по себе канал обновления не открывают.

## Что не блокирует этот релиз

Watchdog зависаний, Ollama/LLM-функции, локальная статистика, Intel/universal.
Это следующие продуктовые этапы, а не долг перед первым релизом мониторинга. Автоматически давать
доверие хукам за пользователя не требуется: явный шаг и проверяемая доставка достаточны.
