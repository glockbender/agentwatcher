# Как macOS-приложение обновляет себя само: версия, карантин, перезапуск

Agent Watch — приложение в строке меню macOS. Оно показывает, чем заняты запущенные сессии Claude Code
и Codex. Раздаётся релизами на GitHub. Здесь — как в нём устроено обновление.

## Задача

Человек скачал версию 0.1.0. О новых версиях он больше не узнает: на страницу релизов никто не ходит
по своей воле. Значит, приложение должно спросить само. И поставить новую версию, если человек
согласен.

## Карантин: кто и что помечает

macOS помечает скачанные файлы. Пометка называется `com.apple.quarantine` и лежит рядом с файлом, в
расширенных атрибутах — это невидимые поля, которые файловая система хранит вместе с файлом.

Помеченное приложение система откроет только с подписью. Подпись — это сертификат от Apple. По нему
macOS видит, кто выпустил программу. Сертификат дают участникам платной программы разработчиков. У
Agent Watch его пока нет, поэтому помеченную копию открыть не удастся.

Но пометку ставит не система. Её ставит тот, кто скачивает файл. Браузер делает это для каждой
загрузки. Проверим: скачаем файл не браузером и посмотрим атрибуты.

```console
$ curl -sL -o AgentWatch.zip https://github.com/.../AgentWatch-0.1.0.zip
$ xattr -l AgentWatch.zip
com.apple.provenance:
```

В ответе одна строка. `com.apple.provenance` — отметка macOS о происхождении файла, она ничего не
блокирует. Строки `com.apple.quarantine` нет. Значит, карантина нет.

Из этого следует всё остальное:

- обновление приложение качает само → пометки нет → ставится и запускается молча;
- первую установку человек делает браузером → пометка есть → нужна одна команда в терминале.

## Один экземпляр

Приложение держит Unix-сокет — файл, через который агенты присылают ему события. Рядом лежит
файл-замок. Вторая копия при живой первой замок не получит и сразу закроется. Это ограничение вернётся
в разделе про перезапуск.

## Как приложение узнаёт о новой версии

Раз в запуск оно делает один запрос к публичному API GitHub — за последним завершённым релизом.
Черновики и сборки с пометкой pre-release этот адрес не отдаёт. Так и нужно: сборку, которую ещё
пробуют, нельзя ставить тем, кто выбрал завершённую версию.

В запросе нет ничего о человеке. Нет даже номера текущей версии: сравнение идёт на его машине.

Дальше решение принимает обычная функция. У неё три входа: своя версия, ответ GitHub и номер версии,
которую человек попросил не предлагать. Выход — один из четырёх ответов. Вот они, прямо из кода:

```swift
public enum AppUpdateDecision {
    case ownVersionUnknown   // нечего сравнивать
    case upToDate            // ничего новее нет
    case skipped(AppRelease) // новее есть, но эту версию просили не предлагать
    case available(AppRelease)
}
```

Функция не ходит в сеть. Поэтому её легко проверить тестами: ответ GitHub подаётся обычной строкой.

Свою версию приложение читает из бандла. Бандл — это папка `AgentWatch.app` с определённой структурой
внутри; в macOS она и есть приложение. При разработке программу запускают прямо из каталога сборки,
бандла нет, версии нет. Тогда проверка молчит. Иначе разработчику каждый запуск предлагал бы обновиться
до версии, которая уже запущена.

Если что-то пошло не так — нет сети, GitHub недоступен, ответ не разобрался, — приложение молчит.
Человек не узнает, что проверка была.

## Как приложение ставит обновление

Сначала оно скачивает архив и сверяет контрольную сумму. Сумма — короткий отпечаток файла: изменился
байт, отпечаток другой. Она лежит в том же релизе отдельным файлом.

От злоумышленника это не защищает: архив и сумма пришли из одного места. Зато ловит обычные беды —
оборванную загрузку, устаревшую копию у посредника, файл, подменённый в момент выкладки.

Распаковка идёт утилитой `ditto`, а не обычным разархиватором. Только она сохраняет символические
ссылки и расширенные атрибуты внутри бандла, а с ними и подпись архива.

Замена старой копии на новую — атомарная. Атомарная значит: либо целиком, либо никак. В macOS для
этого есть готовая операция:

```swift
try FileManager.default.replaceItem(
    at: destination,      // папка, из которой приложение работает сейчас
    withItemAt: staged,   // распакованная новая копия
    backupItemName: nil,
    options: [],
    resultingItemURL: nil
)
```

Почему не «удалить старое, переместить новое»? При таком порядке есть момент, когда приложения на
диске нет. Сбой в этот момент оставит человека ни с чем.

Новая копия распаковывается во временную папку на том же диске. Атомарная замена работает только
внутри одного диска.

Если заменить не вышло — например, у учётной записи нет прав на запись, — ничего не ломается. Новая
копия показывается в Finder, человеку предлагают страницу релиза. Рабочая версия остаётся на месте.

## Перезапуск: где ловушка

Здесь и возвращается ограничение про один экземпляр.

Порядок «запустить новую копию, потом закрыться» не работает. Новая копия стартует, видит занятый
замок и закрывается сама. Через секунду закрывается и старая. Обновление прошло, а приложения на
экране нет.

Обратный порядок невозможен: после закрытия запускать уже некому.

Выход — поручить запуск тому, кто останется жив. Приложение просит оболочку подождать две секунды и
открыть новую копию. После этого закрывается само.

```swift
let task = Process()
task.executableURL = URL(fileURLWithPath: "/bin/sh")
task.arguments = ["-c", "sleep 2; open \(ShellWord.quoted(bundleURL.path))"]
try? task.run()
NSApp.terminate(nil)
```

Двух секунд хватает, чтобы старая копия отпустила замок и сокет.

## Что видит человек

Проверка идёт через пять секунд после запуска. Не сразу — в первую секунду система и так занята.

Если новее ничего нет, человек ничего не увидит. Если есть — появится окно с тремя кнопками:

- **Download** — скачать и поставить;
- **Not Now** — спросят снова при следующем запуске;
- **Skip 0.2.0** — про эту версию больше не спросят, про следующую спросят.

Сборка весит около мегабайта, скачивание занимает доли секунды. Дальше второй вопрос: поставить и
перезапустить.

В меню появился раздел `Updates`. Там видна текущая версия — её первым делом спрашивают у человека,
сообщившего о проблеме. Там же проверку можно выключить совсем.

## Как это проверялось

Решение — обычная функция, и её покрывают тринадцать тестов. Они проверяют всё, что можно перепутать:
своя версия новее, старее или равна; черновик релиза; отложенная версия и следующая за ней; мусор
вместо JSON; релизов нет вовсе. Сеть в этих тестах не нужна.

Остальное тестом не покрыть: сеть, контрольная сумма, распаковка, замена. Для них есть отдельная
проверка. Она ходит в настоящий релиз и включается переменной окружения. В обычном прогоне она
пропускается, чтобы сборка не зависела от доступности GitHub.

```console
$ UPDATE_PROBE_DIR=/tmp/update swift test --filter AppUpdateProbe
latest release: 0.1.0 — https://github.com/.../AgentWatch-0.1.0.zip
unpacked: /var/folders/.../AgentWatch.app
replaced in place: /tmp/update/Target.app is now 0.1.0
```

Три строки — три шага. Нашла последний релиз. Распаковала скачанный архив. Подменила им копию бандла.

Остаются диалоги и перезапуск — то, что делает человек. Их проверяет третий тест, сквозной. Он
собирает копию версии 0.0.9 в отдельной папке и запускает её. Кнопки он нажимает сам — через дерево
доступности, то самое, которым пользуется VoiceOver:

```console
$ task e2e-update
   pressed: Download (after 5s)
   pressed: Install and Relaunch (after 1s)
   the bundle on disk is now 0.1.0
   the old process exited
== PASSED: 0.0.9 → 0.1.0
```

Копия живёт в своей папке и не спорит с рабочей за сокет: в отладочной сборке каталог задаётся
переменной окружения. В раздаваемой сборке этой возможности нет вовсе — проверено, строки нет даже в
бинарнике.

Два места, где тест обманывал сам себя, стоит назвать. Кнопку нельзя искать у процесса по имени:
рабочая копия и тестовая называются одинаково, и система отдаёт первую попавшуюся — тест смотрел в
чужое окно и не находил кнопку. Помогает поиск по номеру процесса. И запускать приложение надо не
напрямую из оболочки, а через `open`: процесс, минующий Launch Services, вообще не попадает в дерево
доступности, хотя окна рисует.

## Что дальше

Первую установку человек пока делает сам, с одной командой в терминале. Убрать эту команду может не
формат файла, а сертификат Apple и нотаризация — проверка приложения на стороне Apple, после которой
система открывает его молча.

Отдельно стоит привычный образ `.dmg` с иконкой и стрелкой на папку Applications. В него можно
упаковать и неподписанное приложение: это просто привычный способ раздачи, а не обход карантина.

На механизм обновления ни то, ни другое не влияет. Он и сейчас качает архив. Образ нужен людям, а не
программе.
