# Рабочие копии и место на диске

Здесь описан отчёт о связанных рабочих копиях Git и известных папках сборки.
Чего здесь нет: управление защитой Git и устройство окна настроек — в [settings.md](settings.md);
порядок дальнейшего развития — в [implementation-plan.md](implementation-plan.md).

Человек выбирает папку одного репозитория и нажимает `Scan Working Copies`. Приложение получает
список через `git worktree list --porcelain -z`: в него входят и копии вне выбранной папки.
Домашняя папка и соседние репозитории не обходятся. При открытии страницы и в фоне сканирование
не запускается. Перед чтением каждой копии проверяется, что она всё ещё принадлежит выбранному
репозиторию. Недоступная или перемещённая папка остаётся строкой с объяснением.

Отчёт показывает ветку, папку, известного владельца, блокировки Git и незавершённые операции.
Владельца подтверждает один обычный файл в служебной папке Git: `claude-desktop-worktree`,
`codex-thread.json` или `mothership-worktree`. Содержимое файла не читается. Отсутствие маркера,
символическая ссылка вместо него или несколько противоречивых маркеров означают неизвестного
владельца. Имя и расположение папки не доказывают принадлежность приложению.

У каждой доступной копии указано, входит ли текущий коммит в историю хотя бы одной известной
Git удалённой ветки. Отчёт проверяет сохранённые локально ссылки, включая коммиты более ранних
версий. Если совпадений нет, изменения могут существовать только на этом компьютере. Состояние
сервера могло измениться после последнего обмена. Проверка истории коммита не учитывает файлы,
которые человек ещё редактирует.

## Что означает размер

Копии отсортированы по убыванию занятого места. В размер копии входят исходники, незарегистрированные
файлы и результаты сборки. Служебные данные Git и вложенные зарегистрированные рабочие копии
исключаются. Символические ссылки не ведут обход за пределы копии. В пределах одного замера
жёсткие ссылки на один файл учитываются один раз. Копии с неизвестным размером стоят внизу.

В раскрытой строке видны размеры известных папок сборки и зависимостей, например `target`,
`.build`, `node_modules`, `dist` и `vendor`. Строка `Known build and cache folders` суммирует
только измеренные папки. Измеряются занятые блоки файловой системы. Разные замеры могут
учитывать одни и те же блоки, а неполный обход даёт неизвестный размер.
Состояние Git показано отдельно для подготовленных к записи изменений, правок отслеживаемых
файлов и новых файлов. Если проверка неполна, это видно в отчёте.

## Когда появляется действие «В Корзину»

В разделе `Settings… → Working Copies` выберите папку репозитория, нажмите `Scan Working Copies`
и раскройте нужную строку. `Move Cache to Trash…` доступно у отдельной папки, которую создавшая
её программа пометила как восстанавливаемую. Например, Cargo записывает такую метку в `target`.
Проверяется начало обычного файла `CACHEDIR.TAG`. Имя каталога и правило исключения Git сами
по себе недостаточны. [Описание метки](https://bford.info/cachedir/).

При незаписанных изменениях, блокировке Git, незавершённой операции или неизвестной занятости
отчёт объясняет причину и оставляет `Show in Finder`. Приложение сверяет рабочие папки наблюдаемых
сеансов с учётом пользовательской настройки чтения метаданных. Для папки с подходящей меткой
дополнительно проверяются открытые файлы и рабочие каталоги процессов текущего пользователя.
Вложенный репозиторий, чужая файловая система или недоступная часть папки также блокируют действие.

Перед подтверждением видны полный путь и измеренный размер. После подтверждения занятость,
состояние Git, содержимое и идентичность каталога проверяются заново. Изменение отменяет
перемещение и обновляет отчёт. При успехе папка оказывается в системной Корзине. Место
освободится после её очистки. Рабочая копия, её ветка и исходники остаются на месте.

## Что взято из Mothership

Из `worktree-cleanup` перенесены разделение отчёта и действия, определение владельца по маркеру,
обработка неизвестности, NUL-разделители списка Git и запрет считать имя папки доказательством
безопасности. Сам скрипт не вызывается: он зависит от Python-модулей Mothership и читает общую
картину процессов и записей клиентов даже при выборе одного репозитория. Внешняя установка
Mothership для этого отчёта не нужна.
